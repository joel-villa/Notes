# Video Streaming and Content Distribution Networks 

- Streaming services = app-level protocols + cachelike servers

## Questions

## 2.6.1 Internet Video 

- Ex: 2 Mbps video for 67 minutes -> 1 gigabyte of storage + traffic
- End-to-end throughput must be larger than the bitrate of the compressed 
  video for continuous play

## 2.6.2 HTTP Streaming and DASH 

- HTTP `GET` request results in a file transfer, the user's app-buffer
    - Con: what about the variability in user's connections?
- *Dynamic Adaptive Streaming over HTTP* (DASH): request chunks of a video 
  file based on current bandwidth (could change even within a single session)
    - high bandwidth -> request high bit-rate version, and vice versa
    - *Manifest File*: provides URL for various versions + bit rates (lives in 
      the HTTP server)

## 2.6.3 Content Distribution Networks 

- Why not a datacenter?
    - Not scalable
    - Single point of failure
- *Content Distribution Networks* (CDNs): "manages servers in multiple
  geographically distributed locations, stores copies of the videos (and other 
  types of Web content, including documents, images, and audio) in its servers
  , and attempts to direct each user request to a CDN location that will 
  provide the best user experience"
- *Private CDN*: owned by content provider (EX: Google's Youtube CDN)
- *Third-Party CDN*: distributes on behalf of multiple content providers
- Two server placemnt philosophies:
    1. *Enter Deep*: Deploy many server clusters in access ISPs (Ex: Akamai)
        - Con: maintenance and managment is crazy
    2. *Bring Home*: larger clusters at a smaller number of sites (EX: 
       Limelight)
        - CDNs placed in Internet Exchange Points (IXPs)
        - easier to maintain, higher delay + lower throughput

### CDN Operation

- Host requests URL, CDN must intercept to redirect the request to a suitable 
  CDN server cluster, 
- How it works:
    - Query an authoratitive DNS for a video link -> DNS provides IP address 
      of the authorative server of the CDN -> establishes TCP connection to 
      the best CDN server cluster
 
### Cluster Selection Strategies

- *Geographically Closest*:
    - Pros: simple
    - Cons: may not be actual fastest
- *Real-Time Measurements*: have CDN cluster probe to every Local DNS, to get 
  a topography
