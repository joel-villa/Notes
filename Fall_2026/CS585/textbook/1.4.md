## 1.4.1 Overview of Delay in Packet-Switched Networks

- Node: a host or router
- **Total nodal delay** = nodal processing delay + queueing delay +
  transmission delay

### Types of Delay

- At node -> In Queue -> Transmission
> "A packet can be transmitted on a link only if there is no other packet 
> currently being transmitted on the link and if there are no other packets 
> preceding it in the queue"

### Processing Delay

- **Processing Delay**: "The time required to examine the packet’s header and 
  determine where to direct the packet" + other things:
    - check bit-level errors
- On the order of microseconds

### Queuing Delay

- **Queuing Delay**: the packet waiting to be transmitted onto the link
- Can be micro to miliseconds
- A function of the intensity and nature of the traffic arriving at the queuea
 
### Transmission Delay

- Length of packet: $L$ bits
- Transmission rate of the link from router to router: $R$ bits/sec
    - EX: Ethernet can big $R$ = 10 Mbps, or 100 Mbps
- **Transmission Delay** = $L / R$
- On the order of microseconds to milliseconds

### Propagation Delay

- **Propagation Delay**: the time required to propage from point A to B
    - Dependent on propagation speed of the link
- EX: twisted-pair copper wire has a propagation speed of $2 \cdot 10^8$ 
  meters/sec to $3 \cdot 10^8$ m/s
- Propagation delay = distance / propagation speed
- On the order of milliseconds

### Comparing Transmission and Propagation Delay

- Transmission Delay is amount of time required to push out the packet 
  (function of packet's length and transmission rate of the link)
- Propagation delay is amount of time it takes a bit to propagate from one 
  router to the next (function of distance between the routers)
- What if propagation delay is less than transmission delay?
    - Bits are arriving at the next router before all have left the first
- Processing delay is often negligible, but is a strong determinant of a 
  router's throuput (maximum rate at which a router can forward packets)

## 1.4.2 Queuing Delay and Packet Loss

- Characterizing queuing delay involves statistical measures: averaging, 
  variance, probability queuing delay exceeds $x$
- Does traffic arrive periodically? Or in bursts?
- **Traffic Intensity** = $La/R$
    - L # of bits per packet
    - a is average rate at which packets arrive at the queue (packets/sec)
    - R is transmission rate (bits/sec)
- If $La/R > 1$, "then the average rate at which bits arrive at the queue 
  exceeds the rate at which the bits can be transmitted from the queue"
- If $La/R \le 1$, then if traffic arrives uniformly there is an average 
  queuing delay of 0, but if it arrives in bursts then the worst case average 
  queuing delay is $\frac{(N-1)L}{2R}$, where $N$ is the number of packets 
- As traffic intensity approaches 1, packet delays approach infinity, when 
  traffic intensity is 1 or higher, then the packet delay is infinite

### Packet Loss

- If a queue is full, packets are dropped, and lost
- Node perfomance is a measure of both delay and probabilty of packet loss 
- Can retransmit lost packets (ensure data transfer)

## 1.4.3 End-to-End Delay

- End-to-end delay of a messsage across $N-1$ routers:

$$
d_{\text{end-end}} = N (\text{processing delay} + \text{transportation delay} 
+ \text{propagation delay})
$$

- Where transportation delay = $L / R$, where L is packet size, and R is rate

### Traceroute

- Traceroute - a program that can run in any Internet host, which tracks a 
  messages path
- If there are $N - 1$ routers between source and destination:
    - Source sends N packets
    - When the i'th packet reaches the i'th router (including destination) it 
      sends a message back to the source, source denotes times and router 
      names/addresses
- The above process is repeated 3 times (to track packet loss)
- Since queuing delay varies over time, n packets sent to router n can 
  sometimes have a longer delay than n+1 packets sent to n+1 routers
- PingPlotter: a GUI for Traceroute

### End System, Application, and Other Delays

- Examples:
    - WiFi or cable modems will purpsoely delay transmission as part of its 
      sharing protocol
    - Voice-over-IP (VoIP) Apps: sending side must fill a packet with encoded 
      digitized speech before passing the packet to the Internet
        - Packetization delay: time to fill a packet

## 1.4.4 Throuput in Computer Networks

- Imagine ttransfering a large file from Host A to Host B:
    - **Instantaneous Throughput** (bits/sec): the rate at which Host B is 
      recieving the file 
- Speedtest application can be used to measure throughput between servers 
  around the internet
- **Average Throughput** = $F/T$
    - Where $F$ is number of bits, and $T$ transfer time
- Balance:
    - Some apps desire low delay and an instantaneous throughput above some 
      threshold (EX: telephony)
    - Other apps only require high throughput (EX: file transfer)
- **Bottleneck Link**: the link in the communication route that has the lowest 
  throughput rate, this determines the throughput rate of the networked-
  communication
    - NOTE: if we send things through the route faster than the bottleneck link 
      can handle, then we will be filling up router queue's
- If the common link in a network has a transmission rate on the same scale 
  as the server access links and client access links, then end-to-end 
  throughput is decreased
