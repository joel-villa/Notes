## 2.1.1 Network Application Architectures

- **Application Architecture**: "designed by the application developer and 
  dictates how the application is structured over the various end systems"
- **Client-Server Architecture**: "there is an always-on host, called the 
  server, which services requests from many other hosts, called clients":
    - Clients do not directly communicate
    - Too many clients -> necessitates multiple servers -> data centers
- **P2P Architecture**: "direct communication between pairs of intermittently 
  connected hosts, called peers":
    - Little or no need for data centers
    - Pros: cost effective, scalable, 
    - Cons: Security, performance, and reliability

## 2.1.2 Processes Communicating

- **Process**: 'program that is running within an end system'
- Processes on two different end systems communicate with each other by 
  exchanign messages across the network
  
### Client and Server Processes

> "In the context of a communication session between a pair of processes, the process that initiates the communication (that is, initially contacts the other process at the beginning of the session) is labeled as the client. The process that waits to be contacted to begin the session is the server" 

### The Interface Between the Process and the Computer Network

- **Socket**: The software interface through which a process sends and 
  receives messages from the network
    > "the interface between the application layer and the transport layer within a host"
    - Sockets can be referered to as the Application Programming Interface 
      (API) between the APP and network
- Programmer has little control over tranport layer side, except for:
    1. Transport Protocol
    2. Transport Layer Parameters (EX: max buffer size, max segment size)

### Addressing Processes

- Identifying the recieving process requires:
    1. Host Address: IP Address
        - **IP Address**: "32-bit quantity that we can think of as uniquely 
          identifying the host"
    3. Process Identifier in the host: port number
- Some popular Apps have specific port numbers:
    - Web -> 80
    - Mail -> 25
    - [[https://www.iana.org/|See Iana For More]]

## 2.1.3 Transport Services Available to Applications 

- Transport-layer protocol has repsonsibility of getting messages to the 
  socket's recieving process
- Whil developing Apps, you must choose between transport layer protocol, and 
  their four possible services:
    1. reliable data transfer
    2. throughput
    3. timing 
    4. security

### Reliable Data Transfer

- How to workaround: buffer overflow, bit corruption, etc?
- **Reliable Data Transfer**: "guarantee that the data sent by one end of the 
  application is delivered correctly and completely to the other end of the 
  application"
- **Loss-Tolerant Applications**: don't care if "some of the data sent by the 
  sending process may never arrive at the receiving process"
    - EX: conversational audio/video (glitches acceptable)

### Throughput

- Does the protocol provide "guaranteed available throughput at some specified 
  rate"?
- **Bandwidth-Sensitive Application**: have throughput requirements
    - EX: Multimedia (though many use techniques to match currently available 
      throughput)
- **Elastic Applications**: "can make use of as much, or as little, throughput 
  as happens to be available"
    - EX: "mail, file transfer, and Web transfers are all elastic applications"
> "one cannot be too rich, too thin, or have too much throughput!"

### Timing

- Constraints on end-to-end delays can be made
    - EX: real-time applications (games, felephony, etc.)

### Security

- Provide confidentiality between two processes through a transport protocol 
  which can encrypt data from sender, and decrypt from receiver
- Other security concerns:
    - data integrity 
    - end-point authentication

## 2.1.4 Transport Services Provided by the Internet

- To UDP or TCP, that is the question (the two transport services 
  provided by the internet)

### TCP Services

- TCP provides the following two services:
    1. Connection-Oriented Service: 
        - Handshaking: "client and server exchange transport-
          layer control information with each other before the application-
          level messages begin to flow"
        - **TCP Connection**: follows handshaking phase, is full-duplex ("the 
          two processes can send messages to each other over the connection at 
          the same time")
        - Involves a tear-down of the connection after messages are done
    2. Reliable Data Transfer Service:
        - All data is sent "without error and in the proper order"
        - Congestion-control: 
            - general Internet welfare rather than for direct benefit of 
              recieving/sending processes
            - Involves throttling of message when network congested
            - Involves limiting esach TCP to a fair share of bandwidth

#### Focus on Secturity: Securing TCP

- **Transport Layer Security** (TLS): provides critical process-to-process 
  security services: encryption, integrity, end-point authentication

### UDP Services

- Connectionless (no handsaking) + unreliable data transfer:
    - No gauruntee on data arrival or ordered arrival
- No congestion-control

## Services Not Provided by Internet Transport Protocols

> "today’s Internet can often provide satisfactory service to time-sensitive 
  applications, but it cannot provide any timing or throughput guarantees"
- TCP:
    - Email, remote terminal, the Web, file transfer
- UDP:
    - telephony (Skype) - wanting to avoid congestion control (but TCP as 
      backup)

## 2.1.5 Application-Layer Protocols

- **Application-Layer Protocl**, defines:
    - Message type (EX: request vs. response)
    - Message syntax (fields in message + delineation betweeen fields)
    - Field semantics (meaning of info in fields)
    - Rules for when and how messages can be sent/responded to
- Some applicational layer protools are in RFCs i.e. public domain:
    - EX: any Web server that uses the HTTP RF C(hyperText Transfer Protocol) 
      can retrieve pages from any other server that follows those same rules
    - CounterEX: Skype's applicaition layer protocol is proprietary
