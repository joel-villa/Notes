## 1.5.1 Layered Architecture

- Analogy: dividing airline travel into layers:
    - Baggage is checked and claimed, gates load and unload, you takeoff on a 
      runway and land on a runway (baggage, gates, runways are the layers)
> "Each layer provides its service by (1) performing certain actions within that layer... and by (2) using the services of the layer directly below it"
- Advantage of layering: modularity

### Protocol Layering

- **Service Model**: the services that a layer offers to the layer above
- Layer protocol implementation (hardware/software):
    > "Application-layer protocols—such as HTTP and SMTP—are almost always implemented in software in the end systems; so are transport-layer protocols. Because the physical layer and data link layers are responsible for handling communication over a specific link, they are typically implemented in a network interface card (for example, Ethernet or WiFi interface cards) associated with a given link. The network layer is often a mixed implementation of hardware and software."
- Distributed networks -> distributed protocols (distributed amongst: end 
  systems, packet switches, etc.)
- Cons of Layering:
    - Duplicate implementations of protocols (Ex: error checking)
    - What if layers are not fully seperated (Ex: I need to know that timestamp 
      value from the other layer)
- **Protocol Stack**: all the protocol layers together (stacked)
    - Five layer protocol stack:
        1. Application
        2. Transport
        3. Network
        4. Link
        5. Physical

### Application Layer

- **Application Layer**: "where network applications and their application-
  layer protocols reside"
    - Protocols: HTTP (Web document request/transfer), SMTP (email transfer), 
      FTP (file transfer)
    - Some Network functions done here (EX: domain name system (DNS) ie the 
      providing of user friendly names)
- **Message**: packet of intfo at the application layer

### Transport Layer

- **Transport Layer**: "transports application-layer messages between 
  application endpoints"
- Transport Protocols:
    1. TCP: connection oriented (sender/receiver speed matching)
        - Congestion control: source throttles transmission rate during 
          congestion
    2. UDP: connectionless service (no reliability, no flow control, no 
       congestion control)
- **Segment**: transport-layer packet

### Network Layer

- **Network Layer**: "responsible for moving network-layer packets known as 
  datagrams from one host to another"
- Gets transport-layer segment + destionation address from Transport Layer, 
  delivers the segment to the transport layer in the destination host
- Includes:
    - IP protocol: defines fileds in the datagram + how end systems and routers 
      act on these fields
        - There exists only one IP protocol
    - Routing Protocols
- Often referred to as teh IP layer

### Link Layer

- **Link Layer**: Move link-layer packets from one network element to the next
- Protocol Examples: Ethernet, WiFi, cable's DOCSIS 
    - Different protocols can be used at different points in a packet's 
      lifespan
- **Frames**: link-layer packets

### Physical Layer

- **Physical Layer**: moves individual bits within the frame from one node to 
  the next
- Protocls are link dependent (EX: twisted-pair vs. fiber optics)
