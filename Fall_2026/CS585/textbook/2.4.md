# 2.4 DNS—The Internet’s Directory Service

- *Hostname*: Identifier for a host (human readable)
- *IP Address*: another identifier for a host (better for locating, and easier 
  for routers to process)
    - Scanning IP addresses left to right reveal more and more local 
      information

## Questions

## 2.4.1 Services Provided by DNS

- *Domain Name System* (DNS): translates human readable hostnames to IP 
  adresses:
    1. DNS is a distributed database (hierarchy of DNS servers)
        - These servers are UNIX based, running Berkeley Internet Name 
          Domain (BIND) software
    2. Application-layer protocol which allows for database queries
        - Runs over UDP on port 53
- To access a host via domain name:
    1. User runs client side of DNS app
    2. browser gets hostname from the URL and passes it to the client side DNS
    3. DNS client receives a reply (which includes an IP address)
    4. Now browser can initiate a TCP connection
- Some other DNS services:
    - *Host Aliasing*: A more readable alias name rather than displaying the 
      cannonical hostname (EX: www.enterprise.com vs. 
      relay1.west-coast.enterprise.com)
    - *Mail Server Aliasing*: Simplify emails (EX: bob@yahoo.com vs. 
      bob@relay1.west-coast.yahoo.com)
- *Load Distribution*: Busy sites can have a set of IP addresses for multiple 
  servers associated with a single hostname
  
## 2.4.2 Overview of How DNS Works

- `gethostbyname()` is the UNIX function to call in order to translate a 
  hostname to an IP address
- Why is the DNS decentralized:
    - More than one server -> a failure doesn't crash entire internet
    - Handles more traffic
    - Put database 'close to' all querying clients
    - Centralization = more frequent updates for new hosts
    - Decentralized = scalable

### A Distributed, Hierarchical Daatabase

- *Root DNS Servers*: provide IP addresses of TLD servers, 1000 root servers, 
  copies of 13 different databases
- *Top-Level Domain (TLD) Servers*: Each top level domain (com, org, net, edu, gov, 
  uk, fr, ca, jp, etc) has an associated TLD server
- *Authoratative DNS Servers*: every org with a web server/mail server must 
  provide a publicly available DNS that maps host names to IP addresses
- *Local DNS Server*: close to the hosts, ISPs give access to these local 
  DNS servers, which act as a layer of indirection

### DNS Caching

- DNS servers discard cached info after a period of time (2 days typically)
- Recall the hierarchy: host bellow authoratative DNS server, below TLD DNS 
  server, below root DNS server
    - TLD servers can also be cached -> very small fraction of DNS queries 
      make it to the root

## 2.4.3 DNS Records and Messages 

- *Resource Records* (RRs): "provide hostname-to-IP address mappings", a four-
  tuple:
    - `(Name, Value, Type, TTL)`
    - `TTL`: time to live: when to remove from cache?
- `Type`:
    - `Type=A` -> `Name` is hostname and `Value` is IP address
        - hostname -> IP Address
    - `Type=NS`: 
        - domain -> authoritative DNS server's hostname
        - EX: `(foo.com, dns.foo.com, NS, TTL)`
    - `Type=CNAME`:
        - alias hostname -> concical hostanme
        - EX: `(foo.com, relay1.bar.foo.com, CNAME)`
    - `Type=MX`:
        - alias hostaname -> canonical hostname of mail server
        - EX: `(foot.com, mail.bar.foo.com, MX)`
        - NOTE: a company could use the same aliase hostname for both their 
          conoical hostname + cononical mail server hostname 
- Authorativive servers have `Type=A` records (can also have a `Type=A` record 
  in cache if non-authorative)
    > "If a server is not authoritative for a hostname, then the server will contain a Type NS record for the domain that includes the hostname; it will also contain a Type A record that provides the IP address of the DNS server in the Value field of the NS record"

### DNS Messages

- There are only two inds of DNS messages, query and reply, they have the 
  same FORMAT:
    - Header Section: 12 bytes
        - 16-bit query id
        - Some flags:
            - reply bit: 0 -> query
            - Authoratative bit: 0 -> not
            - Recursion-desired bit: 0 -> don't do recursion if the server 
              doesn't have the record
        - Four number fields: indicate number of occurences of following 
          sections
    - Question Section:
        1. Name field: Name that is being queried
        2. Type field: Type of question being asked (EX: `Type=A` or `Type=Mx`)
    - Answer Section:
        > "A reply can return multiple RRs in the answer, since a hostname can have multiple IP addresses"
    - Authority Section:
        - records of other authoritative servers
    - Additional Section: 
        - If queried for `Type=Mx`, could return `Type=A` in this section
- `nslookup`: a program on UNIX and Windows, for querying DNS servers of all 
  types
  
### Inserting Records into the DNS Database

- *Registrar*: "commercial entity that verifies the uniqueness of the domain 
  name, enters the domain name into the DNS database (as discussed below), and 
  collects a small fee from you for its services"
- When registering must provide registrar with names and IP addresses of 
  primary + secondary authoratitive DNS servers
> " Suppose Alice in Australia wants to view the Web page www.networkutopia.com. As discussed earlier, her host will first send a DNS query to her local DNS server. The local DNS server will then contact a TLD com server. (The local DNS server will also have to contact a root DNS server if the address of a TLD com server is not cached.) This TLD server contains the Type NS and Type A resource records listed above, because the registrar had these resource records inserted into all of the TLD com servers. The TLD com server sends a reply to Alice’s local DNS server, with the reply containing the two resource records. The local DNS server then sends a DNS query to 212.212.212.1, asking for the Type A record corresponding to www.networkutopia.com. This record provides the IP address of the desired Web server, say, 212.212.71.4, which the local DNS server passes back to Alice’s host. Alice’s browser can now initiate a TCP connection to the host 212.212.71.4 and send an HTTP request over the connection."
