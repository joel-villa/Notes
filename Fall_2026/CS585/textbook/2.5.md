# 2.5 Peer-to-Peer File Distribution

- When sending a large file to many hosts in a network, the server would be 
  overwhelmed if not for peer-to-peer distribution
- BitTorrent: "most popular P2P file distribution protocol" (2020)

## Scalability of P2P Architectures

- $u_s$: uppload rate of server's access link
- $u_i$: uppload rate of i'th peer
- $d_i$: download rate of i'th peer
- $F$: file size
- $N$: number of peers that desire a copy
- *Distribution Time*: "time it takes to get a copy of the file to all $N$ 
  peers"
- Distribution time for a client-server architechture
    - where $d_{\min}$, is the rate of the peer with the lowest download rate
$$
D_{CS} = \max \{\frac{NF}{\mu_s}, \frac{F}{d_\min}\}
$$
- Distribution time in P2P
$$
D_{P2P} = \max \{ \frac{F}{\mu_s}, \frac{F}{d_{\min}}, \frac{NF}{\mu_s + 
\sum_{i=1}^N \mu_i}\}
$$

- If $F/u = 1$ hour, client-server architecture will linearly increase in $N$,
  but P2P will simply approach 1
  
## BitTorrent

- torrent: collection of all peers
- chunk size = 256KBytes
- Track: a torrent's infrastructure node
- Steps:
    1. Join torrent -> recieve random subset of torrent's peers' IPs
    2. Attempt to establish TCP connections iwth those peers (# of peers can 
       fluctuate as people join and leave)
    3. Anyone in the torrent will have a subset of the chunks of the file, 
       must request peer's chunk lists periodically
    4. Which chunks to request? 
        - *Rarest First*: "from among the chunks she does not have, the chunks 
          that are the rarest among her neighbors and then request those 
          rarest chunks first"
        - Goal: uniform distribution of chunks
    5. Who to send to?
        - Have four *unchoked* peers (those sending most amount of bits), and 
          one *optimisticallly unchoked* peer to send bits to at random
        - Goal: peers with compatible rates find eachother
