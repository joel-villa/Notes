# 3.4 Principles of Reliable Data Transfer 

## TLDR

- Building a Reliable Data Transfer Protocol
    - Bit errors are handled through acknowledgeements + checksum + sequence 
      number
    - Packet loss is handled through timeouts
- Go-Back-N:
    - Recievers do not buffer, if packets are recieved out of order, send 
      error immediately, and Sender will resend everything to be safe
- Selective Repeat (SR):
    - Recievers do buffer, if packets are recieved out of order, reciever 
      will only request those which actually contain error

## Definitions

- *Unidirectional data transfer*: "data transfer from the sending to the 
  receiving side"
- *ARQ (Automatic Repeat reQuest) protocols*: positive + negative
  acknowledgements, that data has been received, and what was recieved 
  malformed
- *alternating-bit protocol*: "packet sequence numbers alternate between 0 and 1
  , protocol rdt3.0"
- *Pipeling*: "the sender is allowed to transmit... packets before having to 
  wait for acknowledgments"
- *Go-Back-N* (GBN) protocol: In a Go-Back-N (GBN) protocol, the sender is 
  allowed to transmit multiple packets (when available) without waiting for an 
  acknowledgment, but is constrained to have no more than some maximum 
  allowable number, N, of unacknowledged packets in the pipeline."
