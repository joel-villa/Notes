## Multiplexing/Demultiplexing

- How to seperate data reliably?
- Sender -> multiplexing:
    - Add information to our transport header
- Reciever -> demultiplexing
    - Where to send the data that I am recieving? 

- Server knows the client's port# + ip address: appends that to messages
- Client recieves message, reads header, sends to appropriate process on 
  appropriate port

### Demultiplexing

- Recieving packet, where to send it to?
- This demultiplexing happens at transport layer

### Multiplexing

- Sending packet from a port, must add header of destination

### How DeMultiplexing works

- Internet protocol => IP address
- Transport layer => port number
- Transport layer header fields must include sender port # + reciever port #

### Connectionless Demultiplexing

- UDP: connectionless
- Must still bind to a port number, but do not care about IP address
- Doesn't need to know anything about source as reciever, i.e.
    - All it needs to know is destination IP address + destination port #
- When dealing with UDP, one server will use the same socket for all clients
    - Always using the same port number
    - One port number + one socket

#### Example

- WHat to include in transport layer header: source port + destination port
- NOTE: only one socket necessary
    - With TCP need one socket per client

### Connection-Oriented Demultiplexing

- Need the four things in the header: src IP + port #, and dest IP + port #
- As a server can have multiple sockets on a single port number
    - Distinguishing through the quad-tuple
    - Virtualization: multiple sockets on the same port
